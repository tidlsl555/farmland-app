## 출시 범위

이번 7일 목표는 대규모 상용 확장이 아니라 **제한된 사용자 대상 Release Candidate**다.

- 현재 81개 농지를 그대로 유지한다.
- Android Chrome/삼성 인터넷 + HTTPS PWA를 1차 지원 범위로 둔다.
- 지도, 빠른 작업, 물관리, 지번 검색, 장치 저장, 인증된 세션의 서버 저장/Realtime을 검증한다.
- 결제, 공개 회원가입, 대규모 멀티테넌트 운영, 외부 고객 자동 메시지는 이번 출시 범위에서 제외한다.
- 비로그인 상태는 항상 `기기 저장 모드`로 표시하며 서버 저장으로 표현하지 않는다.
- 로그인 오버레이를 다시 강제하지 않는다. 제한 출시 사용자는 별도의 안전한 1회 등록/초대 절차로 세션을 만든 뒤 세션을 유지하는 방식을 우선 검토한다.

## P0 출시 차단 항목

### P0-1 지도 구현 기준 일치

현재 배포 경로와 저장소의 OpenLayers 기반 `src/app.js`가 서로 다른 UI 계열로 존재한다. 실제 배포 번들에서 OpenLayers가 현재 지도 런타임에 사용되는지 증명하고, 아니라면 기존 UX를 손상시키지 않는 범위에서 OpenLayers 단일 구현으로 정리한다.

**통과 기준**
- 배포 산출물에서 실제 지도 런타임이 OpenLayers임을 자동/수동 증거로 확인.
- 81개 레코드와 기존 작업/물관리 데이터 구조가 유지됨.
- 모바일에서 지도 이동/확대/필지 탭/선택 상태가 회귀하지 않음.

### P0-2 81필지 정확 위치

seed에는 81개 레코드가 있으나 정확 좌표 여부는 서버/현장 자료로 별도 검증해야 한다. 근사 좌표는 정확 좌표로 승격하지 않는다.

**통과 기준**
- 81/81 각각에 대해 `exact`, `gps_verified`, `manual_verified` 중 허용 상태와 근거가 남음.
- 필지 경계가 필요한 항목은 유효한 Polygon/MultiPolygon이 존재함.
- 주소/지번/표시번호 ↔ 지도 객체 1:1 대조표 작성.
- 동일 위치에 잘못 겹친 핀, 누락 지도 객체 0건.
- 검증 실패 항목이 있으면 출시 차단 또는 명시적 제외 범위로 승인받음.

### P0-3 서버 저장과 인증 경계

비로그인 세션은 장치 저장만 사용한다. 서버 저장을 사용하려면 사용자를 식별하고 조직 RLS를 적용할 인증 세션이 필요하다.

**통과 기준**
- 비로그인: 서버 쓰기 0건, UI에 `기기 저장 모드` 표시.
- 인증 사용자: 자신의 org 데이터만 읽기/쓰기 가능.
- 다른 org 계정으로 교차 읽기/쓰기 시도 시 거부.
- 로그인 오버레이를 기본 앱 진입 장벽으로 다시 도입하지 않음.
- 제한 출시 등록 절차(예: 관리자 초대 + 1회 magic-link 등록)를 문서화하고 이후 세션 유지 확인.

### P0-4 VWorld 단일 서버 경로

현재 배포 번들은 Netlify VWorld 함수 URL을 하드코딩하고 있고 저장소에는 Supabase Edge Function 구현도 존재한다. 운영 경로를 하나로 통합한다.

**권장 순서**
1. Supabase `vworld-parcel-sync`를 staging에서 배포.
2. `VWORLD_API_KEY`, 허용 Origin 등 서버 비밀/설정을 서버 환경에만 구성.
3. 인증/관리자/org 범위/VWorld exact match를 테스트.
4. PWA를 `supabase.functions.invoke('vworld-parcel-sync')`로 전환.
5. Netlify 경로 의존 제거 후 release audit 통과.

**통과 기준**
- 브라우저 배포물에 VWorld 비밀키/service role key 없음.
- 비관리자 호출 403, 비로그인 401.
- 다른 org farmlandId로 경계 저장 불가.
- 정확한 리+지번 매칭 결과만 저장.

### P0-5 다중기기/오프라인 충돌

현재 PWA 서버 동기화는 전체 JSON 상태를 `app_states` 한 행에 upsert하는 구조이므로 동시 편집 시 last-write-wins 데이터 손실 위험을 반드시 검증/해결한다.

**최소 출시안**
- `revision` 기반 optimistic concurrency(CAS)를 도입한다.
- 저장 RPC가 `expected_revision`과 현재 revision 불일치 시 overwrite하지 않고 conflict를 반환한다.
- conflict 시 원격 상태를 가져오고 작업/물관리 append-only 로그를 기준으로 안전 병합하거나 사용자에게 명시적 재조정 상태를 보여준다.
- 오프라인 쓰기를 허용한다면 로컬 pending mutation queue에 mutation id를 부여하고 재전송 중복을 방지한다.

**통과 기준**
- 두 기기가 같은 필지를 순차/동시에 변경하는 테스트에서 조용한 덮어쓰기 0건.
- offline A 변경 → online B 변경 → A 재접속 시 데이터 손실 없이 충돌 처리 증거.
- 동일 mutation 재시도 시 중복 로그가 생기지 않음.

### P0-6 백업/복구

IndexedDB 복구본은 장치 손상에 대비한 서버 백업이 아니다.

**통과 기준**
- 장치 localStorage → IndexedDB 복구 테스트 성공.
- 서버 DB 백업 절차와 보관 위치/주기/담당자 문서화.
- production을 직접 덮지 않고 staging/복구용 DB에 restore drill 1회 성공.
- 복구 후 81필지, 작업/물관리 이력, 권한 데이터 개수/무결성 대조.

### P0-7 공급망/빌드 보안

현재 기준 CI `npm ci`에서 보안 취약점 경고가 발생했다.

**통과 기준**
- `npm audit` 원인 패키지/영향 경로 기록.
- high 취약점은 수정 또는 실제 비영향 근거와 승인 기록.
- release build와 `npm run release:audit` 통과.

## P1 개선

- `APP_BUILD`/`SEED_VERSION` 내부 표기를 실제 RC 버전으로 갱신하고 화면/로그에 표시한다.
- 사용하지 않는 `src/app.js` 등 병렬 UI 경로는 삭제가 아니라 먼저 참조 관계를 증명한 뒤 quarantine/deprecation 처리한다.
- Vite의 non-module `pwa-inline-*` 경고를 의도된 구조인지 문서화하거나 모듈 구조로 정리한다.
- 지번 검색이 공개 CORS proxy/Naver 비공식 응답에 의존한다면 서버측 VWorld 검색으로 통합한다.
- 관측성: release id, sync 상태, 마지막 성공 저장 시각, conflict 수, boundary 실패 수를 진단 화면에 표시한다.

## 사업화 가설

### 초기 고객 가설
1. 다수 필지를 관리하는 농업법인/영농조합/대농.
2. 농작업 대행·방제·물관리 조직.
3. 여러 작업자가 같은 농지를 공유 관리하는 조직.

### 가격 검증 가설
가격은 확정하지 말고 고객 인터뷰에서 3개 anchor를 테스트한다.

- Basic: 월 9.9만원 — 소규모 조직, 핵심 지도/작업/물관리.
- Team: 월 19.9만원 — 다중 작업자, realtime, audit/backup.
- Operations: 월 49.9만원 이상 — 다수 필지/관리자/리포트/지원.

이는 시장가격 사실이 아니라 **지불의사 검증용 가설**이다. 면적/필지수/작업자수 기반 가격도 함께 비교한다.

### 수요 검증
- 타깃 고객 인터뷰 10건.
- 실제 현장 파일럿 2곳 이상 또는 유료 전환 의향서/구체적 가격 반응 확보.
- 측정: 주간 사용자 수, 필지 탭/작업기록 수, 동기화 성공률, 종이/엑셀 대비 기록시간, 오류/누락 감소, 지불의사.

- VWorld/API 및 지도 트래픽.
